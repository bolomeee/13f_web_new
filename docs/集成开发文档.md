## 1. 集成目标 (Integration Goal)

本项目旨在将已完成的 React 前端（基于 Mock 数据）对接至 Python 后端。后端需接管数据的所有权，提供 RESTful API 供前端调用，并负责核心的 SEC 13F 数据抓取、清洗及差异计算（Diff Calculation）。

**技术栈要求**：
* **后端框架**：**Django 5.0+** (强烈推荐)。因其 ORM 对 SQLite 支持完美，且自带 Admin 后台方便调试数据，非常适合本项目。
* **数据库**：**SQLite 3**。利用 Python 标准库，文件存储，零配置，适合个人轻量级应用。
* **异步任务**：**Celery + Redis**。用于处理 SEC 爬虫（耗时操作）和手动触发的更新任务。
* **API 规范**：RESTful JSON。

## 2. 数据库模型设计 (Database Schema)

基于前端展示需求设计的核心实体关系。所有表结构需通过 Django ORM (`models.py`) 实现。

**SQLite 适配特别说明**
* **Decimal (金额/比例)**: 在 Django ORM 中定义为 `DecimalField`，Django 会自动处理 SQLite 中的精度转换。
* **Enum (Action Type)**: SQLite 不支持枚举类型，ORM 需将其映射为 `CharField` (字符串，如 "BUY", "SELL")。
* **UUID**: 建议作为主键。Django 默认支持在 SQLite 中将 UUID 存储为 32 位字符串。

### 2.1 核心表结构 (Core Tables)

1.  **Institution (机构表)**
    * `id`: UUID (Primary Key)
    * `cik`: Char(10), Unique, Indexed (SEC 索引键)
    * `name`: Varchar (机构名称, e.g., "Berkshire Hathaway")
    * `avatar_initials`: Char(3) (前端展示用的缩写, e.g., "BH")
    * `aum`: Decimal (总资产管理规模)
    * `is_active`: Boolean (是否在监控列表中, default=True)
    * `created_at`: Datetime (auto_now_add=True)

2.  **Filing (申报文件表)**
    * `id`: UUID (Primary Key)
    * `institution_id`: ForeignKey -> Institution (Indexed)
    * `period_of_report`: Date (报告期截止日, e.g., 2024-12-31)
    * `filing_date`: Date (实际提交日)
    * `accession_number`: Varchar (SEC 唯一文件编号，用于去重)
    * `quarter`: Varchar (e.g., "Q4 2024")

3.  **Holding (持仓明细表)**
    * `id`: UUID (Primary Key)
    * `filing_id`: ForeignKey -> Filing (Indexed)
    * `ticker`: Varchar (股票代码, Indexed)
    * `company_name`: Varchar
    * `cusip`: Varchar
    * `share_count`: BigInt (持股数量)
    * `value`: Decimal (市值)
    * `pct_portfolio`: Decimal (仓位占比)
    * **Diff Fields (后端计算后存入)**:
        * `share_change`: BigInt (较上季度变动股数)
        * `pct_change`: Decimal (较上季度变动百分比)
        * `action_type`: Varchar (存储 'NEW', 'Buy', 'Sell', 'Sold Out', 'Hold')

4.  **OptionPosition (期权持仓表)**
    * `id`: UUID (Primary Key)
    * `filing_id`: ForeignKey -> Filing (Indexed)
    * `ticker`: Varchar
    * `option_type`: Varchar (存储 'CALL', 'PUT')
    * `contracts`: BigInt (合约数量)
    * `notional_value`: Decimal (名义价值)

5.  **CrawlLog (爬虫日志表)**
    * `id`: AutoIncrement Int (Primary Key)
    * `status`: Varchar ('SUCCESS', 'ERROR')
    * `filings_processed`: Integer
    * `error_message`: TextField
    * `timestamp`: Datetime (auto_now_add=True)

## 3. API 接口规范 (API Specification)

严格遵循前端 `mockData.ts` 的结构，确保前端无需修改 TypeScript 接口定义。

### 3.1 仪表盘数据 (Dashboard)

**GET /api/dashboard/summary**
* **用途**：一次性获取 Dashboard 所需的所有聚合数据。
* **Response Structure**:
    ```json
    {
      "top_picks_cards": [
         // 对应 TopPicksColumns 的4列数据 (Highest Increase, Highest Decrease, Consensus Buy, Consensus Sell)
         {
             "type": "highest_increase",
             "items": [ { "ticker": "NVDA", "name": "NVIDIA", "institution": "Fisher", "value": 25.7 } ]
         },
         ...
      ],
      "recent_activity": [
        // 对应 ActivityFeed
        {
          "id": "uuid-string",
          "guruName": "Berkshire Hathaway",
          "action": "buy",
          "ticker": "AAPL",
          "changePercent": 12.4,
          "date": "2026-01-28"
        }
      ]
    }
    ```
   

### 3.2 机构详情 (Institution Details)

**GET /api/institutions/{id}**
* **用途**：获取单个机构的详情页数据。
* **Response**:
    ```json
    {
      "id": "uuid-string",
      "name": "Berkshire Hathaway",
      "aum": 360000000000,
      "increasedPositions": [ { "ticker": "AAPL", "shares": 100, "change": 10, ... } ],
      "decreasedPositions": [ ... ],
      "callOptions": [ { "ticker": "TSLA", "contracts": 50, "totalValue": 100000 } ],
      "putOptions": [ ... ]
    }
    ```
   

### 3.3 设置与管理 (Settings & Admin)

**GET /api/admin/companies**
* **返回**：`MonitoredCompany[]` 列表。

**POST /api/admin/companies**
* **Request**: `{ "cik": "0001067983" }` 或 `{ "ticker": "BRK-B" }`
* **逻辑**：后端调用 SEC API 或本地缓存验证 CIK -> 获取标准公司名 -> 存入数据库 `Institution` 表。

**DELETE /api/admin/companies/{id}**
* **逻辑**：级联删除该机构及其所有 Filing、Holding 数据。

**GET /api/admin/system-status**
* **返回**: `{ "success_count": 1247, "error_count": 23 }` (基于 `CrawlLog` 表统计)。

**POST /api/crawler/trigger**
* **用途**：手动触发更新。
* **返回**: `{ "task_id": "celery-uuid", "status": "started" }`。

### 4.2 差异计算引擎 (Diff Engine Implementation)

**任务**：移植 `EDGAR/demo_13f_changes.py` 的对比逻辑。

* **触发时机**: 4.1 入库事务完成后。
* **逻辑移植**:
    * **上季数据源**: 改为查询数据库 `Filing.objects.filter(...).order_by('-period_of_report').first()`。
    * **算法复用**: 保持原有的 Set 集合运算逻辑（`current_tickers - prev_tickers` = New Entries）。
    * **回写**: 计算出的 `action_type` (New/Buy/Sell/Sold Out) 和 `pct_change` 直接更新回 `Holding` 表。
    * **Sold Out 处理**: 对于已清仓股票，在 `Holding` 表中插入一条 `share_count=0, action_type='Sold Out'` 的记录，以便前端查询。

## 6. 任务调度配置 (Task Scheduling)

为了实现 Settings 页面中的 "Update Frequency" 功能，配置 Celery Beat：

* **Daily**: 每天凌晨 2:00 运行 `crawl_all_institutions` 任务。
* **Weekly**: 每周五收盘后运行。
* **Manual**: 当调用 `/api/crawler/trigger` 时，立即异步调用 `crawl_all_institutions.delay()`。
